# 索克家居 × 智能家居联动 · 裸眼3D / VR 漫游可行性分析

> 日期：2026-08-12
> 定位：基于 2026 技术前沿与行业最新进展的可行性分析（研究性质，不涉及代码改动）
> 范围：裸眼3D 展示、VR/WebXR 漫游，与索克家居既有智能家居体系的联动方案

---

## 1. 项目现状盘点（联动基础）

索克家居已具备完整的「设计 → 施工 → 智能家居」数据链，为 3D/VR 联动提供了现成底座：

| 能力域 | 现状 | 联动价值 |
|---|---|---|
| VR 全景 | 后端 `app/api/vr_panorama.py`：panoramas（360°）+ hotspots（热点跳转）+ scenes（多全景组合漫游） | 已有内容模型，可直接叠加设备图层 |
| 3D 渲染 | webapp `PanoramaViewer.jsx`（Three.js 360° 查看器，含低配设备降级） | 前端 3D 底座已就绪 |
| AR 扫描 | `/api/ar/*`：RoomPlan / LiDAR / 设备能力检测 / 降级链 | 户型 3D 数据来源 |
| AI 渲染 | `/api/ai-render`：ControlNet L0→mock→占位→error 4 级降级链 | 效果图/3D 场景生成 |
| 智能设备 | `SmartDevice` 模型（位置坐标 position_x/y/z）+ Matter/Zigbee 协议 | **3D 场景中的设备锚点** |
| 场景自动化 | `SceneAutomation` + 传感器快照真实触发（2026-08-12 已修复落库） | 3D 漫游中实时反映场景状态 |
| 生态桥接 | HomeKit / 米家 / 鸿蒙 / Matter / 涂鸦 5 类桥（Matter 已可实现） | 真实设备控制通道 |
| 语音交互 | Qwen-Audio-3.0-Realtime 实时双工 + 语音编排 | 「看着说」的免手交互入口 |

**核心结论**：索克家居不缺 3D/VR 的「骨架」，缺的是「空间 × 设备 × 状态」三者的实时联动层——这正是本分析的发力点。

## 2. 2026 技术前沿与行业进展

### 2.1 VR 漫游（房产/家装行业已验证）

- **WebXR 浏览器原生化**：2025 年底起所有主流浏览器支持 WebXR，用户**无需头显、无需下载 App** 即可浏览器内漫游（PC/手机通用），头显用户（Meta Quest / Apple Vision Pro）自动升级沉浸模式。
- **数据验证**：UT Dallas 2025 研究（43,000 套房源）显示 VR 看房将平均成交周期从 34 天降至 19 天（**-44%**）；带 3D 看房的房源浏览量多 87%。—— 卖得更快，且不抬高售价（诚实口径）。
- **步进式漫游成熟**（蛙色 720 等）：AI 特征点自动三维重建，智能测距还原空间布局，20 分钟完成 100㎡ 建模，多终端展示，热度/标注/一键导览成标配。
- **AI 全屋场景生成**：ACE ROBOTICS 2026-06 开源 **Kairos-HomeWorld**——首个从单条 prompt 生成「全屋可交互 3D 场景」的 World Model：30 万真实中国户型 + 5,000 套仿真家居 + 50,000 可交互物体资产，四阶段架构（户型生成→2D/3D 提升→递归精修→可操作物放置），专为机器人训练与仿真设计。
- **Web 3D 引擎**：A-Frame（Mozilla）已集成 **3D Gaussian Splatting** 与 Text-to-3D AI 内容补全，Three.js 为底层（项目已在用）。

### 2.2 裸眼3D（2026 拐点年）

- **政策**：2026-06 商务部等八部门《关于加快"人工智能+消费"发展的实施意见》将「裸眼3D、VR/AR 沉浸式体验」列为重点培育新业态；2025 国内裸眼3D 屏市场 85 亿元，**2026 预计突破 110 亿元**。
- **两条技术路线**：
  1. LED 2D 屏 + 物理弯角：成本低、可复制，但立体感依赖「最佳观看位」，偏离即失效。
  2. 真裸眼3D（光场 / 柱状透镜 / 视差屏障）：左右眼分别成像，视角内均有效。代表：光子晶体科技 nanoAR™ 体全息光场透明屏（透光率 >90%、2K~8K、宽视角，屏幕即玻璃）。
- **消费级落地**：
  - ViewX Liber 15.6"（2026-05，¥7999）：超表面液晶透镜，2D/3D 一键无损切换，180fps 眼动追踪动态调视角，内置 AI SoC 实时 2D→3D 转换。
  - 三星 LF-1130 光场屏（11.3"，120° 视角、1500nit、眼动追踪，已量产商用）。
  - 京东方 **DepthForge 1.0**（2026-06）：全球首款大模型裸眼3D 内容生成平台，普通 2D 视频/图片数分钟生成多视角深度素材，速度提升约 20 倍、8K 输出。
- **前沿研究**：清华大学 **SSS-LiD**（Nature Photonics 2026-06）——超宽角低像差光学 + 整体机械同步扫描，150° 视角下分辨率较商用方案提升 2~2.5 倍，串扰 <3%。
- **行业挑战**：光场屏制造成本高（商用万元级）、动态内容视觉疲劳未完全解决、内容生态薄弱（原生3D 片源稀缺）、缺乏统一格式标准（中国标准化研究院 2026-10 已发布《裸眼3D显示舒适度评价规范》草案）。

## 3. 联动架构：3D 空间即智能家居入口（数字孪生）

核心设计思想：**把「3D 漫游」从展示工具升级为智能家居的第三交互入口**（与 App、语音并列）。

```
┌─────────────────────────────────────────────────┐
│ 表现层  裸眼3D 大屏 │ WebXR 漫游 │ App 3D 视图      │
├─────────────────────────────────────────────────┤
│ 空间层  Three.js / WebGPU / Gaussian Splatting   │
│        全景球体 · 3D 户型 · 实景重建               │
├─────────────────────────────────────────────────┤
│ 联动层  DeviceOverlay(设备锚点) · StateLayer     │
│        实时状态(开关/温湿度/占用) · 场景状态高亮    │
├─────────────────────────────────────────────────┤
│ 交互层  点击热点(开/关/调光) · 语音(看着说)       │
│        场景一键触发(回家/观影)                    │
├─────────────────────────────────────────────────┤
│ 数据层  SmartDevice · SceneAutomation ·          │
│        SensorSnapshot(2026-08-12 已真实落库)     │
├─────────────────────────────────────────────────┤
│ 桥接层  EcosystemBridge(Matter/米家/鸿蒙/涂鸦)    │
└─────────────────────────────────────────────────┘
```

**三个关键联动点**：

1. **设备锚点**：`SmartDevice` 已含 `position_x/y/z` + `room_name`，可在 3D 场景中直接定位设备。渲染时把设备状态（在线/离线、开关、亮度、色温）映射为空间内的可视化标记与交互热点——现有 `PanoramaViewer` 热点机制（yaw/pitch Sprite）已具备承载能力。
2. **状态实时化**：传感器快照（真实落库）+ 场景触发日志驱动 3D 场景状态刷新（如「高温联动」触发后，场景中空调/灯的状态同步更新）；WebSocket（项目已有 `ws_manager`）可做状态推送。
3. **控制回写**：3D 场景内点击/语音触发设备动作 → 场景自动化/生态桥执行 → `action_status=pending`（桥接未接真机前诚实标注，不伪装已执行）。

## 4. 三条可行路径（渐进式，风险递增）

### 路径 P0：720° 步进漫游 + 设备热点联动（推荐先行）

- **做什么**：基于现有 `PanoramaViewer`（已用 Three.js）升级为步进式漫游——房间间通过热点跳转；每个设备热点显示实时状态，点击唤起语音/控制；场景状态在 3D 中高亮（如「回家模式」点亮全屋灯）。
- **技术栈**：Three.js（已有）+ `/api/vr/*`（已有）+ `/api/smart-home/*`（已有）+ WebSocket 状态推送。
- **与智能家居联动**：最直接——「漫游即控制」，无需任何新硬件。
- **成本/风险**：低。工作量集中在联动层（DeviceOverlay + 状态映射），复用率高。
- **商业价值**：B 端展示（售楼处/装企）+ C 端体验，UT Dallas 数据（-44% 成交周期）可直接引用。

### 路径 P1：Gaussian Splatting 实景漫游 + AI 场景生成

- **做什么**：用手机/LiDAR 采集实景 → 3D Gaussian Splatting 重建真实空间（替代贴图全景，支持自由视角微移动）；接入 AI 场景生成（对标 Kairos-HomeWorld：户型 prompt → 全屋可交互 3D，或 2D 效果图 → 3D 化）。
- **技术栈**：A-Frame/Three.js + Gaussian Splatting 插件；AI 生成接入现有 LLM 多 provider fallback 链。
- **与智能家居联动**：重建场景中自动摆放设备锚点（AI 识别家具/设备 → 关联 `SmartDevice`）。
- **成本/风险**：中。采集端需 SDK/App 支持；Gaussian 渲染对 WebGPU/移动端性能有要求（需降级链：无 WebGPU 回退贴图全景，延续项目 4 级降级纪律）。

### 路径 P2：裸眼3D 展示（展厅/大屏/营销）

- **做什么**：利用索克家居已有的 3D 模型/效果图资产，生产裸眼3D 内容（对接 DepthForge 类 AI 2D→3D 管线），在品牌展厅/装修博览会/售楼中心用裸眼3D 屏展示「设计方案 + 智能家居场景」。
- **与智能家居联动**：展示态的联动（预设场景循环演示：回家/观影/睡眠模式在 3D 空间中的光影效果），非控制态。
- **成本/风险**：高。硬件万元级 + 内容制作成本是 2D 的 5-10 倍 + 视觉疲劳与标准未定。适合作为**品牌营销的增量**，不建议作为主力交互入口。
- **2026 窗口**：政策扶持（AI+消费）+ 市场破百亿 + 内容生成 AI 化（DepthForge 类工具将制作成本拉低 20 倍）——2-3 年内值得关注，当前阶段建议以「低成本试水」为主（如租用商用裸眼3D 屏 + AI 生成 3D 内容做展会演示）。

## 5. 技术选型对比

| 维度 | P0 全景漫游 | P1 Gaussian 实景 | P2 裸眼3D |
|---|---|---|---|
| 内容来源 | 效果图/实拍全景（已有管线） | 手机采集 + AI 重建 | 3D 资产 + AI 2D→3D |
| 前端技术 | Three.js（已有） | Three.js + GS 插件 | 大屏端 SDK / DepthForge |
| 设备联动 | 点击/语音热点（直接） | 设备锚点自动摆放 | 演示态（间接） |
| 硬件依赖 | 无（浏览器即可） | WebGPU/高配移动端 | 裸眼3D 屏（万元级） |
| 成本 | 低 | 中 | 高 |
| 风险 | 低 | 中（性能降级） | 高（内容/标准/疲劳） |
| 建议 | **2026 优先落地** | 2026-2027 试点 | 品牌营销期试用 |

## 6. 风险与诚实降级约束

1. **设备控制未接真机**：生态桥（HomeKit/米家/鸿蒙/涂鸦）多数仍为 TODO stub，3D 场景触发设备动作须沿用 `action_status=pending` 诚实标注，禁止伪装「已执行」。
2. **WebXR 需 HTTPS**：生产已为 443 + LE 证书（架构红线已满足），`wss://` 可复用。
3. **低配设备**：延续项目 4 级降级纪律（WebGPU → WebGL → 贴图全景 → 静态图），PanoramaViewer 已有 low-end 降级先例。
4. **裸眼3D 疲劳/标准**：内容帧率/视差需对齐《裸眼3D显示舒适度评价规范》草案方向，避免差评口碑。
5. **数据诚实**：3D 场景中的设备状态必须来自真实落库（SensorSnapshot/SceneBehaviorLog），不渲染假状态。

## 7. 结论与建议

1. **P0 立即可行**：在现有 PanoramaViewer + `/api/vr/*` + `/api/smart-home/*` 之上增加「设备热点联动层」，即可交付「720° 漫游即控制」的智能家居 3D 入口。这是投入产出比最高、且不与架构红线冲突的路径。
2. **P1 是中期方向**：Gaussian Splatting 实景重建 + AI 全屋场景生成（Kairos-HomeWorld 开源可借鉴）将带来「真实空间 × 可交互设备」的量级体验，适合作为 2026-2027 技术预研。
3. **P2 裸眼3D 定位为营销增量**：政策窗口 + 硬件降价趋势（2027 面板成本预计 -40%）值得保持跟踪，当前以低成本展会试水为主，不做主力投资。
4. **联动数据底座已就绪**：本轮（2026-08-12）修复的传感器真实落库 + 场景触发闭环，正是 3D 漫游「状态实时化」的数据前提——联动层可以直接消费这些真实数据。
