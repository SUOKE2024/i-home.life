## 执行摘要

索克家居(i-home.life)是一个**生产级家装全流程 AI 平台**:Python(FastAPI)后端 **25 Agent(21 执行型 + 4 商业运营)+ 1 Orchestrator** + **80 个 API 路由模块(83 处 include_router)** + **111 个 Service** + **140 个 ORM 模型(140 张表)**,Flutter 多端(iOS/Android/HarmonyOS)55 页面 + React Web 控制台 66 页面 + webapp(Vite+React)主页,自研 **MCP Server 完整落地 2026-07-28 规范 8 项**(11 业务 + 6 管理工具)+ **A2A v1.0(2026-03)双协议在线**,自建 **AgentTrace + IHomeEval + Skill 自进化数据飞轮**对标赛题两大基础设施之一 **AgentLoop**(持续进化维度),并新增 **空间数字底座 Robot-Ready Home**(确定性空间语义 + 渲染一致性校验,对标 SpatialLM/SpatialGen/大晓 Kairos-HomeWorld),**2442 项 pytest 基线全绿**。

本方案以赛题必选的 **AgentTeams(阿里云 2026-07-14 公测 / WAIC 2026-07-18 Agent Native Cloud 核心产品 / 开源 Hiclaw)** 为多 Agent 协同设计基点,把 i-home.life 已验证的真实全链路能力(AR 量房→设计→预算→采购→施工→质检→结算→智能运营→平台自治)映射为 **1 编排器 + 8 领域 Worker** 的协同体系:编排层(AgentTeams Manager-Workers + Matrix 透明房间 + 零信任凭证收敛)负责任务拆解/上下文传递/人机协同,工具层(ihome-mcp Skill → i-home.life MCP Server)以标准协议把真实业务工具暴露给 Worker,业务层零改动。

**核心差异**:竞品(飞流AI 3.1/三维家/欧派/酷家乐/Homeglow AI)侧重单点设计或单环节能力;索克是"全流程多 Agent 自主协同 + 标准协议基础设施"——**能力可组合、可迁移、可审计**,并以诚实降级(L0-L3/源标注)保证"不伪装能力"。

**v1.6.0 自治运营升级(借鉴 Polsia 一人公司 + 义乌「AI 嵌入生意每一环」)**:在 21 个执行型 Agent(家装交付链路)之上,新增 4 个**平台商业运营 Agent**——growth(功能使用率周报)/marketing(多渠道获客素材)/competitor_research(竞品调研)/finance_recon(平台财务对账),由 OrchestratorAgent.generate_daily_briefing 每日聚合运营简报,阿里云 FC 定时触发器调用 `/api/admin/daily-briefing`(无 K8s/Cron)。这使索克从"AI 装修工具平台"升级为"AI 自治运营的装修生意平台"——Agent 不仅服务用户交付,还自治运营平台自身。

**v1.13.x 生产级 Agent 工程闭环(2026 前沿落地)**:Agent 自进化管线(P0 Case 提取 + P1 Skill 蒸馏/注入/进化,借鉴 EverMind EverOS/SkillCorpus/HarnessBank)、工具纪律(契约 required + use-example + typed 校验 + 有 db 串行/无 db 并行 + token 预算早停 + 56 用例工具准确率评估)、可观测编排评估三层(AgentTrace 落库 + workflow_id 传播 + 漂移检测 + `/api/agents/orchestrate` 编排 API + IHomeEval 13 维 + OWASP Agentic Top 10 治理审计 + LLM usage 成本追踪)、用户满意度质量门禁(feedback_like_rate_min 70%)——对齐 GOAI 赛道「团队协同、可验证可回滚、持续进化」三维考察。

### 1.1 行业范式转移:从"像素生成"到"空间智能"

《2026 中国智能家装设计行业发展白皮书》(2026-04,中国建筑装饰协会联合发布,120 页)首次系统定义**空间智能**:家装 AI 已从"像素生成"演进为"物理感知",三大核心能力:

| 能力 | 定义 | 索克对应落地 |
|---|---|---|
| **空间感知** | 看懂户型,识别墙体/门窗/承重结构 | AR 空间测量(4 级降级 + RMS 精度报告)、DXF/CAD 导入、草图转 3D、户型 SSOT(floorplan.data) |

### 2.6 协议层:MCP 2026-07-28 规范 8 项 + A2A v1.0 双协议

**MCP(自研,纯 Python,零第三方 SDK)**:
- `stateless`:无握手、无 Mcp-Session-Id,round-robin 负载均衡
- `server/discover`:能力发现 RPC 替代旧 manifest
- `header-routing`:`Mcp-Method`/`Mcp-Name` 头优先于 body
- `cacheable`:`tools/list` cache_hint + ETag(MD5 内容哈希)+ 字典序,If-None-Match → 304
- `MRTR`:多轮往返服务端→客户端请求(采样/elicitation,5min TTL,asyncio.Future)
- `RFC 9207 + CIMD`:`POST /api/mcp/cimd`(替代 DCR,对标 OAuth 2.1)
- `Tasks` 扩展:tasks/create|update|get|list|cancel,状态机对标 A2A TaskState
- `Server Card`:`GET /.well-known/mcp` 公开
- **`W3C Trace`(对齐 MCP SEP-414)**:JSON-RPC 响应 `_meta` 注入 `traceparent/tracestate/baggage`,与 OpenTelemetry GenAI Span 打通,AgentTrace 开箱即对齐标准
- **`Enterprise Readiness`(对齐 MCP 2026 Roadmap)**:以 MCP 扩展暴露审计/SSO/gateway 模式——复用既有 HMAC 审计、WebAuthn/PASETO SSO、stateless 无状态网关,`mcp_enterprise_extension_enabled=True` 默认开启

**A2A v1.0**:`/.well-known/agent-card`(公开 22 个 Agent 技能)+ tasks/send(经 Harness 执行)+ tasks/{id} 状态查询,任务持久化 a2a_tasks 24h TTL。与 MCP Tasks 互补:跨 Agent 委托 vs 单 Agent 异步长任务。
