## 执行摘要

索克家居(i-home.life)是一个**生产级家装全流程 AI 平台**:Python(FastAPI)后端 24 个 Agent 模块 + **658 条 API 路由(73 个模块)** + **95 个 Service** + **121 个 ORM 模型**,Flutter 多端(iOS/Android/HarmonyOS/Web)42 个页面 + React Web 控制台 35 个页面,自研 **MCP Server 完整落地 2026-07-28 规范 8 项** + **A2A v1.0(2026-03)双协议在线**,并以自建 AgentTrace + IHomeEval 数据飞轮**对标赛题两大基础设施之一 AgentLoop**(持续进化维度)。

本方案以赛题必选的 **AgentTeams(阿里云 2026-07-14 公测产品 / 开源 Hiclaw)** 为多 Agent 协同设计基点,把 i-home.life 已验证的真实全链路能力(AR 量房→设计→预算→采购→施工→质检→结算→智能运营)映射为 **1 编排器 + 8 领域 Worker** 的协同体系:编排层(AgentTeams Manager-Workers + Matrix 透明房间)负责任务拆解/上下文传递/人机协同,工具层(ihome-mcp Skill → i-home.life MCP Server)以标准协议把 11 个真实业务工具暴露给 Worker,业务层零改动。

**核心差异**:竞品(飞流AI 3.1/三维家/欧派/酷家乐)侧重单点设计或单环节能力;索克是"全流程多 Agent 自主协同 + 标准协议基础设施"——**能力可组合、可迁移、可审计**,并以诚实降级(L0-L3/源标注)保证"不伪装能力"。

### 2.6 协议层:MCP 2026-07-28 规范 8 项 + A2A v1.0 双协议

**MCP(自研,纯 Python,零第三方 SDK)**:
- `stateless`:无握手、无 Mcp-Session-Id,round-robin 负载均衡
- `server/discover`:能力发现 RPC 替代旧 manifest
- `header-routing`:`Mcp-Method`/`Mcp-Name` 头优先于 body
- `cacheable`:`tools/list` cache_hint + ETag(MD5 内容哈希)+ 字典序,If-None-Match → 304
- `MRTR`:多轮往返服务端→客户端请求(采样/elicitation,5min TTL,asyncio.Future)
- `RFC 9207 + CIMD`:`POST /api/mcp/cimd`(替代 DCR,对标 OAuth 2.1)
- `Tasks` 扩展:tasks/create|update|get|list|cancel,状态机对标 A2A TaskState
- `Server Card`:`GET /.well-known/mcp` 公开
- **`W3C Trace`(对齐 MCP SEP-414)**:JSON-RPC 响应 `_meta` 注入 `traceparent/tracestate/baggage`,与 OpenTelemetry GenAI Span 打通,AgentTrace 开箱即对齐标准
- **`Enterprise Readiness`(对齐 MCP 2026 Roadmap)**:以 MCP 扩展暴露审计/SSO/gateway 模式——复用既有 HMAC 审计、WebAuthn/PASETO SSO、stateless 无状态网关,`mcp_enterprise_extension_enabled=True` 默认开启

**A2A v1.0**:`/.well-known/agent-card`(公开 22 个 Agent 技能)+ tasks/send(经 Harness 执行)+ tasks/{id} 状态查询,任务持久化 a2a_tasks 24h TTL。与 MCP Tasks 互补:跨 Agent 委托 vs 单 Agent 异步长任务。

### 2.8 可观测与持续进化:对标赛题 AgentLoop 数据飞轮

> 赛题明确 AgentLoop(阿里云 2026-07-14 公测)为两大基础设施之一,对应"持续进化"考察维度。AgentLoop 核心是**数据飞轮**:Trace→Trajectory→Dataset/Experience→优化→更高质量 Trace。索克以自研 AgentTrace + IHomeEval + DSPy 落地同理念(非直连阿里云 AgentLoop 产品,而是对标其范式自建)。

**数据飞轮四环(对标 AgentLoop):**

| 环 | AgentLoop 概念 | 索克落地 | 证据 |
|---|---|---|---|
| ① 采集 | 无侵入采集链路/指标/日志 | OTel GenAI Span + SSE thinking_step + 工具调用链全量记录;**MCP 响应 `_meta` 注入 W3C Trace(SEP-414)** | `app/observability/` + `/metrics` + `app/mcp/server.py` |
| ② 轨迹 | Trace→Trajectory(清洗组装) | AgentTrace 还原"用户输入→模型推理→工具调用→RAG→决策分支→回复"完整路径,含 token/耗时/降级原因 | `/api/agents/{id}/traces` |
| ③ 评估 | Agent-as-a-Judge(评估器即 Agent) | IHomeEval 10 维评估 + DSPy BootstrapFewShot 离线评估 + HC 约束校验(rebuttal_engine 反合理化)+ 图纸比对 | `app/eval/` |
| ④ 经验 | Experience 经验库→反馈优化 | AgentFeedback 表 → L4 偏好自适应学习(few-shot 注入)+ Skill 版本管理 + 评估 Badcase 回归集 | `AgentFeedback` ORM + `config/intent_contract.json` CI 强制校验 |

**经验自进化(对标 AgentLoop 核心卖点"越用越聪明",无需重训模型):**
- 成功轨迹提炼有效路径 → 沉淀为 few-shot 示例 → 下次同类任务注入提示
- 失败轨迹归因(超支/越权/降级/幻觉)→ 反馈 rebuttal_engine 强化 HC 约束 → 回归测试拦截
- L4 自适应:用户偏好(风格/预算/品牌)持续学习 → 个性化推荐权重更新

**诚实边界:** 索克自建评估飞轮对标 AgentLoop 范式,未接入阿里云 AgentLoop 商业产品;Agent-as-a-Judge 评估器基于 IHomeEval 10 维,非全量人类专家评估。复赛计划:构建 Golden/Badcase 评测集(参照 suoke_life 11 例),补强 Trajectory→Experience 自动挖掘闭环。
